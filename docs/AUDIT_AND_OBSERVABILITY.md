# Audit and Observability
# ClaimPilot India — Logging, Metrics, and Tracing Reference

**Version**: 1.0  
**Authority**: All logging must conform to this specification. Deviation makes debugging impossible.

---

## Correlation ID System

Every operation in the system is traceable via two IDs:

### Request ID (`requestId`)
- Generated at the API gateway (Express middleware) for every inbound HTTP request
- Format: `req_` + 16 hex characters, e.g. `req_7f3a91b2c4d6e8f0`
- Injected into every log line, audit event, and database write produced by that request
- Returned to the client in the `X-Request-ID` response header

### Job ID (`jobId`)
- Generated by M6 (Orchestration) when a background job is enqueued
- Format: `job_` + 16 hex characters
- Traces asynchronous processing that happens after the HTTP request returns
- Links background module executions back to the originating request

### Claim ID (`claimId`)
- The persistent identifier linking all events across a claim's lifetime
- All log lines for claim processing include `claimId`
- Enables filtering all events for a single claim: `grep claimId=clm_abc123 server.log`

### How They Work Together
```
HTTP Request arrives:
  requestId = req_7f3a91b2c4d6e8f0

User uploads documents:
  log: { requestId, claimId, action: "DOCUMENTS_RECEIVED" }
  audit_log: { requestId, claimId, event_type: "DOCUMENTS_UPLOADED" }

M6 enqueues OCR job:
  jobId = job_a1b2c3d4e5f6g7h8
  log: { requestId, jobId, claimId, action: "OCR_JOB_ENQUEUED" }

M2 executes OCR (later, async):
  log: { jobId, claimId, action: "OCR_STARTED" }
  log: { jobId, claimId, action: "OCR_COMPLETED", confidence: 0.91 }
  audit_log: { jobId, claimId, event_type: "OCR_COMPLETED" }
```

## Structured Log Format

All logs are emitted as single-line JSON. Never multi-line. Never plain text.

### Log Entry Schema

```json
{
  "timestamp":  "ISO-8601 string",
  "level":      "DEBUG | INFO | WARN | ERROR | CRITICAL",
  "moduleId":   "M1_SPEECH_INTELLIGENCE | M2_DOCUMENT_INTELLIGENCE | ...",
  "requestId":  "req_... | null (for background jobs)",
  "jobId":      "job_... | null (for request-scoped operations)",
  "claimId":    "clm_... | null (for non-claim operations)",
  "userId":     "usr_... | null (for system-initiated operations)",
  "event":      "snake_case event name",
  "message":    "human-readable description",
  "data":       { "...context-specific key-value pairs..." },
  "durationMs": "number | null (for operations with measurable duration)",
  "error":      { "code": "...", "message": "...", "stack": "..." }
}
```

### Log Level Definitions

| Level | When to Use | Examples |
|---|---|---|
| `DEBUG` | Detailed tracing for development | "Prompt composed, token count: 1842" |
| `INFO` | Normal operations worth recording | "OCR completed, confidence: 0.91" |
| `WARN` | Unexpected but handled situations | "Low confidence transcript, routing to human review" |
| `ERROR` | Failures that affect a single claim | "Gemini API timeout on attempt 2" |
| `CRITICAL` | System-wide failures or data integrity issues | "Database locked for > 10s", "API key missing" |

## Registered Audit Events

Every event in `audit_log` must use one of these registered event types. No ad-hoc event strings.

### Claim Lifecycle Events

| Event Type | Module | Trigger |
|---|---|---|
| `CLAIM_CREATED` | M6 | New claim record created |
| `CLAIM_ABANDONED` | M6 / M7 | Claim terminated by human or timeout |
| `CLAIM_COMPLETE` | M6 | Claim reached terminal success state |
| `CLAIM_STATE_CHANGED` | M6 | Any state transition (includes from/to) |

### Document Events

| Event Type | Module | Trigger |
|---|---|---|
| `DOCUMENTS_UPLOADED` | API / M2 | Files received and saved to disk |
| `DOCUMENT_DUPLICATE_REJECTED` | M2 | SHA-256 hash matches existing document |

### M1 — Speech Intelligence Events

| Event Type | Trigger |
|---|---|
| `TRANSCRIPTION_STARTED` | M1 begins Whisper call |
| `TRANSCRIPTION_COMPLETED` | Whisper returns successfully |
| `TRANSCRIPTION_FAILED` | All retries exhausted |
| `TRANSCRIPTION_LOW_CONFIDENCE` | Confidence < 0.75, human review triggered |

### M2 — Document Intelligence Events

| Event Type | Trigger |
|---|---|
| `OCR_STARTED` | M2 begins processing |
| `OCR_PAGE_FAILED` | Individual page OCR fails (non-terminal) |
| `OCR_COMPLETED` | All documents processed |
| `OCR_FAILED` | All documents unreadable, all retries failed |

### M3 — Clinical Structuring Events

| Event Type | Trigger |
|---|---|
| `STRUCTURING_STARTED` | M3 begins Gemini call |
| `STRUCTURING_RETRY` | API failure, retrying |
| `STRUCTURING_COMPLETED` | Extraction successful |
| `STRUCTURING_FAILED` | All retries failed |
| `STRUCTURING_LOW_CONFIDENCE` | Confidence < threshold, human review triggered |

### M4 — Medical Coding Events

| Event Type | Trigger |
|---|---|
| `CODING_STARTED` | M4 begins code validation |
| `CODE_VALIDATED` | Individual code confirmed valid |
| `CODE_INVALID` | Individual code not in ICD-10 dataset |
| `CONFLICT_DETECTED` | Code conflict identified |
| `CODING_COMPLETED` | All codes processed |
| `CODING_REQUIRES_HUMAN` | requiresHumanCoding = true |
| `CODING_FAILED` | All retries failed |

### M5 — Claim Validation Events

| Event Type | Trigger |
|---|---|
| `VALIDATION_STARTED` | M5 begins rule evaluation |
| `VALIDATION_RULE_PASSED` | Individual rule passes |
| `VALIDATION_RULE_FAILED` | Individual rule fails |
| `VALIDATION_COMPLETED` | All rules evaluated |
| `MISSING_DATA_DETECTED` | Required fields absent |

### M6 — Orchestration Events

| Event Type | Trigger |
|---|---|
| `ORCHESTRATION_DECISION` | M6 decides next action after state change |
| `JOB_ENQUEUED` | Job added to processing queue |
| `JOB_DEQUEUED` | Job picked up for execution |
| `JOB_COMPLETED` | Job finished |
| `JOB_FAILED` | Job failed, retry or escalate |

### M7 — Human Review Events

| Event Type | Trigger |
|---|---|
| `HUMAN_REVIEW_REQUESTED` | M7 creates review record |
| `HUMAN_REVIEW_REMINDER` | 24h timeout reminder sent |
| `HUMAN_REVIEW_ESCALATED` | 48h timeout escalation sent |
| `HUMAN_REVIEW_DECIDED` | Human submits decision |
| `HUMAN_DATA_ENTRY_COMPLETED` | Human provides missing fields |
| `CLAIM_APPROVED_BY_HUMAN` | Final approval granted |
| `CLAIM_REJECTED_BY_HUMAN` | Final approval rejected |

### M8 — Submission Events

| Event Type | Trigger |
|---|---|
| `SUBMISSION_ATTEMPT` | M8 begins submission attempt |
| `SUBMISSION_ATTEMPT_FAILED` | Single attempt fails, will retry |
| `SUBMISSION_SUCCESS` | Insurer accepts claim |
| `SUBMISSION_REJECTED` | Insurer returns rejection |
| `SUBMISSION_ALL_ATTEMPTS_FAILED` | All retries exhausted |
| `DENIAL_ANALYSIS_STARTED` | M3/M4 re-run for denied claim |
| `DENIAL_ANALYSIS_COMPLETED` | AI recommendation ready |

### Security Events

| Event Type | Trigger |
|---|---|
| `AUTH_LOGIN_SUCCESS` | Successful login |
| `AUTH_LOGIN_FAILED` | Invalid credentials |
| `AUTH_TOKEN_EXPIRED` | JWT expired |
| `AUTH_UNAUTHORIZED_ACCESS` | Request to protected route without token |
| `AUTH_INVALID_TOKEN` | Tampered or malformed JWT |
| `SENSITIVE_DATA_ACCESS` | Any read of patient data (DPDPA compliance) |
| `SETTINGS_CREDENTIAL_UPDATED` | Insurer credential changed |
| `USER_CREATED` | New user account created |
| `USER_ROLE_CHANGED` | User role modified |

## Performance Metrics

These metrics are computed and queryable via M9 (Analytics) and also logged periodically:

### Module Performance Metrics

| Metric | Definition | Target |
|---|---|---|
| `m1.transcription_latency_p95` | 95th percentile Whisper API latency | < 30s |
| `m2.ocr_latency_p95` | 95th percentile per-document OCR time | < 60s |
| `m3.structuring_latency_p95` | 95th percentile Gemini extraction time | < 10s |
| `m4.coding_latency_p99` | 99th percentile coding time (local, should be fast) | < 2s |
| `m5.validation_latency_p99` | 99th percentile validation time | < 100ms |
| `m8.submission_latency_p95` | 95th percentile submission time | < 60s |

### Claim Processing Metrics

| Metric | Definition |
|---|---|
| `claim.time_to_approval_minutes` | CREATED → AWAITING_HUMAN_APPROVAL |
| `claim.time_in_human_review_minutes` | Time from review request to decision |
| `claim.total_processing_minutes` | CREATED → COMPLETE |
| `claim.retry_rate` | % of claims that trigger at least one module retry |
| `claim.human_intervention_rate` | % of claims that require human data entry |

### AI Quality Metrics

| Metric | Definition |
|---|---|
| `m3.extraction_confidence_avg` | Average extraction confidence across all claims |
| `m3.missing_fields_avg` | Average missing fields per claim |
| `m4.coding_confidence_avg` | Average coding confidence |
| `m4.conflict_rate` | % of claims with at least one coding conflict |
| `m5.first_pass_rate` | % of claims passing validation on first attempt |

### System Health Metrics

| Metric | Definition |
|---|---|
| `queue.depth` | Current job queue length |
| `queue.oldest_job_age_seconds` | Age of oldest unprocessed job |
| `db.query_latency_p95` | Database query latency |
| `api.request_rate` | Requests per second |
| `api.error_rate` | % of requests returning 4xx or 5xx |

## Dashboard Metrics (Visible to Hospital Staff)

These are the metrics surfaced in the ClaimPilot dashboard (Screen2 in wireframe):

| Displayed Metric | Source |
|---|---|
| "Claims This Month" | COUNT(claims) WHERE created_at >= start of month |
| "Approval Rate" | COUNT(insurer_approved) / COUNT(submitted) |
| "Revenue Recovered" | SUM(estimated_cost_inr) WHERE status = INSURER_APPROVED |
| "Avg Processing Time" | AVG(time from CREATED to AWAITING_HUMAN_APPROVAL) in minutes |
| "Recovery Rate" | COUNT(DENIAL_RESUBMIT) WHERE eventually approved / COUNT(INSURER_REJECTED) |

All dashboard metrics are hospital-scoped — a user can only see metrics for their hospital.

## Log Retention

| Log Type | Retention | Storage |
|---|---|---|
| `audit_log` table | Permanent (legal requirement) | SQLite → archive after 90 days |
| Application logs (JSON files) | 90 days rolling | Log file rotation |
| Security events | 1 year | Separate security log file |
| Raw LLM responses | 30 days (debugging only) | In `claim_structured_data.raw_llm_response`; purged after 30 days |
| Playwright screenshots | 180 days (submission evidence) | `uploads/screenshots/` |
