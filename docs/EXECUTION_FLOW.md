# Execution Flow

> A precise description of what happens from `npm run dev` to what the user sees in the browser.

---

## 1. Development Server Startup

```
npm run dev
```

Executes: `vite --port=3000 --host=0.0.0.0`

Vite:
1. Reads `vite.config.ts`
2. Loads environment variables from `.env.local` (user-created) and `.env.example`
3. Injects `process.env.GEMINI_API_KEY` into the client bundle
4. Applies the React plugin (`@vitejs/plugin-react`) for JSX transformation
5. Applies the Tailwind CSS plugin (`@tailwindcss/vite`) for utility class generation
6. Starts the dev server on `http://0.0.0.0:3000`

---

## 2. Browser Request

User opens `http://localhost:3000`

Vite serves `index.html`:
```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My Google AI Studio App</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

---

## 3. Module Resolution

Browser loads `/src/main.tsx` (transpiled by Vite/esbuild):

```typescript
import {StrictMode} from 'react';
import {createRoot} from 'react-dom/client';
import App from './App.tsx';
import './index.css';

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

Vite resolves the import chain:
- `main.tsx` → `App.tsx` → `WireframeUI.tsx`, `AuthScreens.tsx`, `DashboardScreens.tsx`, `ClaimScreens.tsx`, `PipelineScreens.tsx`, `DenialScreens.tsx`
- `index.css` → Tailwind CSS utility classes (generated by Vite plugin)
- All lucide-react icon imports

---

## 4. React Mount

`createRoot` mounts `<App>` into `<div id="root">`.

**Strict Mode** causes every component to render twice in development (intentional React behavior for detecting side effects).

---

## 5. App Component Render

`App.tsx` renders:

```jsx
<div id="canvas-container" className="w-screen h-screen overflow-auto bg-gray-200 relative font-sans">
  <div className="absolute top-4 left-4 ...">
    ClaimPilot India - Wireframe Map (Scroll to pan)
  </div>
  
  <div className="relative" style={{ width: 8000, height: 6000 }}>
    <ArrowsOverlay connections={connections} />
    
    {/* 16 screens at absolute positions */}
    <div className="absolute top-[100px] left-[100px]"><Screen1 /></div>
    <div className="absolute top-[100px] left-[1300px]"><Screen2 /></div>
    ...
  </div>
</div>
```

The outer `div` is `overflow-auto` — the user can scroll/pan horizontally and vertically.  
The inner `div` is a fixed 8000×6000px canvas — all screens positioned absolutely within it.

---

## 6. ArrowsOverlay Execution

`ArrowsOverlay` component runs its `useEffect`:

1. Immediately calls `updateLines()` after mount
2. Sets a 1-second `setTimeout` to call `updateLines()` again (for post-layout settle)
3. Adds `resize` event listener

`updateLines()` iterates `connections[]`:
```javascript
connections.map(conn => {
  const fromEl = document.getElementById(conn.from);  // Find source button
  const toEl = document.getElementById(conn.to);      // Find target screen
  
  const fromRect = fromEl.getBoundingClientRect();
  const toRect = toEl.getBoundingClientRect();
  
  const container = document.getElementById('canvas-container');
  // Offset by scroll position
  const startX = fromRect.right - containerRect.left + container.scrollLeft;
  const startY = fromRect.top + fromRect.height/2 - containerRect.top + container.scrollTop;
  const endX = toRect.left - containerRect.left + container.scrollLeft;
  const endY = toRect.top + toRect.height/2 - containerRect.top + container.scrollTop;
  
  return { startX, startY, endX, endY, id };
})
```

Sets state with line coordinates → triggers re-render → SVG paths drawn.

---

## 7. Screen Render

Each of the 16 screen components renders a `1024×768px` wireframe panel using the shared primitives from `WireframeUI.tsx`. All data is hardcoded strings within JSX.

---

## 8. Final User Experience

The user sees:
- A gray background canvas
- A "ClaimPilot India - Wireframe Map (Scroll to pan)" label in top-left
- 16 screen panels arranged in a 6-column grid
- Dashed black Bezier arrows connecting buttons to their target screens
- Everything is static — hovering and scrolling work; clicking buttons does nothing

---

## 9. No Backend Calls

There are **zero network requests** after the initial page load. No fetch, no XHR, no WebSocket, no API calls of any kind. The `@google/genai` SDK is installed but never imported or called.

---

## Build Flow (Production)

```
npm run build
```

Executes: `vite build`

Output: `dist/` directory (not present in repo)
- `dist/index.html` — entry HTML
- `dist/assets/index-[hash].js` — bundled JS
- `dist/assets/index-[hash].css` — extracted CSS

This static bundle can be deployed to any static hosting or Cloud Run container.

---

## Type Check (Lint)

```
npm run lint
```

Executes: `tsc --noEmit`

Only checks TypeScript types. Does not run ESLint, Prettier, or any other linter.

**Known issue**: Because all `WireframeUI` props are typed as `any`, TypeScript provides no type safety on component props across the codebase.
